## Claims verified by VER (reference facts)
- source: VER
- Google Android (13 Nov 2025): ~0.2 memory-safety vulnerabilities per MLOC of Rust vs "closer to 1,000" per MLOC historically for C/C++; applies to new code, not translated code.
- C-to-Rust Fallacy, arXiv 2609.25682 (22 Sep 2026): 116 Juliet programs, 464 Rust outputs; 342 failed to compile, 177 inherited original memory bugs, 77 new bugs.
- Sharma et al., CCS 2024 (arXiv 2311.05063): c2rust fails on 93.8% (15/16) of embedded codebases; failed outright on 6 of 16 RTOSes; 9 of the 10 that ran produced incorrect or invalid Rust; embedded crates use ~2x the unsafe blocks.
- ORBIT, arXiv 2604.12048: 100% compilation and 91.7% test success.
- RustAssure, arXiv 2510.07604: 89.8% of C functions translated to compilable Rust; 69.9% of those produced equivalent symbolic return values.
- TRACTOR, arXiv 2609.25121 (20 Sep 2026): correctness is "behavioral fidelity to the compiled C binary"; unsafe measured semantically by compiler instrumentation.

## Literature findings (LIT Key Findings)
- source: LIT
DATA_Nb9fT1sM_START
1. Single-shot LLM translation is weak; scaffolded agentic pipelines are strong on benchmarks. 2. The tests are the weak link (vanilla agents pass while covering 64.4% of functions and 3.0% of test cases). 3. Static ownership inference has a known ceiling (Aliasing Limits 12% -> 21%; Crown median 37.3%). 4. Formal equivalence works only on small or restricted code (VERT BMC 1% -> 42%; Mini-C subset). 5. Safety is not the same as security; reducing unsafe counts is a poor proxy.
DATA_Nb9fT1sM_END

## Human versus AI responsibility split
- source: LIT section (c)
DATA_Pj5gW2uH_START
Human-owned: equivalence contract and UB policy; oracle/validation architecture; pipeline architecture; spot-review of high-risk semantic diffs; approval of data-structure redesigns; unsafe/FFI boundary; embedded/hardware semantics; shipped-configuration selection; security review; performance budgets; evaluation methodology (hidden tests, semantic unsafe, agents never see acceptance tests); customer "done" definition and liability. LLM-delegable behind deterministic gates: UB inventories drafts, fuzz/property/Kani harness drafts, translation, compile-error repair, unsafe-elimination refactoring, bindgen glue, macro translation, Cargo features, sanitizer/fuzzer runs and triage, report drafts. LLMs demonstrably fail at: single-shot ownership reasoning, off-by-one and pointer-increment semantics, honest self-assessment, preserving security properties, hardware knowledge outside the code.
DATA_Pj5gW2uH_END

## Open problems (moat) versus borrow
- source: LIT section (e)
- Moat: refinement-based equivalence with UB policies and automatic UB-input characterization; compositional equivalence across divergent structures; hardware-aware equivalence; configuration-space validation; necessary versus laundered unsafe; security-preservation checks.
- Borrow: c2rust, Crown hints, Hayroll, idiom lifters (check licences and maintenance), skeleton-first dependency-ordered orchestration (ORBIT, EvoC2Rust, His2Trans), LLM repair loops, fuzzers/KLEE/Kani/CBMC/Miri/sanitizers, TRACTOR schema and tools.
