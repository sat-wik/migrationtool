## ADR-0001: Write the migration tool in Rust
- source: /home/claude/migrationtool/docs/adr/0001-tool-implementation-language.md
- status: locked (Accepted, LOCKED; manifest precedence 0)
- decision: The tool is written in Rust as a Cargo workspace. External analysers (clang/LLVM, KLEE, c2rust, Hayroll, Kani, Bear) are invoked as pinned subprocesses inside a reproducible container, not linked as libraries. The LLM agent loop is also Rust, behind a model-agnostic provider trait so hosted and locally hosted open-weight models are interchangeable. Python may appear only in throwaway research scripts under `research/`, never in the shipped tool.
- scope: Rust, Cargo workspace, migration tool, clang/LLVM, KLEE, c2rust, Hayroll, Kani, Bear, LLM agent loop, provider trait
- consequences (from source): one static binary per platform for air-gapped installs and signed releases; tool and its output share a toolchain, Clippy and rustfmt conventions; agent-loop iteration is slower than in Python, mitigated by a small, well-tested provider and prompt-template layer.
- alternatives considered (from source): Rust; Python; Rust core with a Python agent loop.
- deciders: Satwik (date 2026-10-07)
