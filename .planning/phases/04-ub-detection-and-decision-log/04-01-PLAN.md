<objective>
Close runner residual WR-13 (D-24) before any forking analyser (KLEE, the sanitizer variants) runs through the runner: after the drain grace, and on the timeout path, find the processes that hold this run's output pipes through `/proc/*/fd` and kill them with a pidfd, so an escapee can no longer keep a stream open.

Purpose: the UB pass and the KLEE scan run thousands of subprocesses; a stream left open by an escapee makes a run incomplete and its evidence unusable. CONTEXT D-24 orders this plan first and D-26 places it in step 1.

Output: the sweep in runner.rs, `exit.pipe_holders_killed`, run-record schema 3, two rewritten tests and two new ones, and a green ci run.

This file also holds the "Phase 4 shared rules" section that every other Phase 4 plan references.
</objective>

## Phase 4 shared rules (binding for every Phase 4 plan)

Every Phase 4 plan lists this file in its context and follows this section.

**Branch and push.** Push only when `git rev-parse --abbrev-ref HEAD` prints `claude/gsd-discuss-phase-1-mzdw5v`, and only with `git push -u origin claude/gsd-discuss-phase-1-mzdw5v`. Never force, never push main, never rebase, never create or push another branch. On a network failure retry the same push up to 4 times, waiting 2 s, 4 s, 8 s and 16 s, then stop and report. Before every push run the pre-merge gates `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test --workspace --locked && cargo deny check`.

**Tool code (CLAUDE.md, ADR-0001).** `#![forbid(unsafe_code)]` in every crate; `thiserror` in libraries, `anyhow` only in `mt-cli`; no `unwrap`/`expect` outside tests without an invariant comment; every subprocess through `mt_toolchain::runner` (clippy bans `std::process::Command` elsewhere); `BTreeMap` and sorted vectors; `schema_version` on every file format; no timestamps outside manifest headers; tests never use the network or a live model; every requirement has a test whose name contains its ID in snake case (`ub_01_` .. `ub_05_`; runner tests keep `tool_01_`). Test files start with `#![allow(clippy::unwrap_used, clippy::expect_used)]`.

**Wording.** Reports, notices, docs and log text never contain the two forbidden claim words (checked with the regex `certif[i]ed|complia[n]t`). A clean vector is reported as "no UB observed by <variants>", an unlabelled unchecked one as "UB unchecked", a timeout as "not proven", a missing layer as "unavailable". Never the bare phrase "no UB".

**Signing.** Only the founder signs. No agent writes `approver`, `date` or `rationale` into any committed `testbed/ub-log/*.toml` or `testbed/policy/*.toml`, and no agent runs `mt ub sign` against the committed test-bed logs (D-28, D-35). Test fixtures under `crates/*/tests/fixtures` may carry the test approver `test-approver`.

**CI protocol.** Evidence comes only from `gh api repos/sat-wik/migrationtool/actions/...` and check-run annotations, read with `gh api --paginate repos/sat-wik/migrationtool/check-runs/<job_id>/annotations --jq '.[] | "== " + .title + "\n" + .message'` (parts of one title joined with a newline, in order). Poll every 60 s (one Bash call is limited to 10 minutes). A run still going 15 minutes after its `timeout-minutes` is stuck: stop and report. Any `gh api` failure: stop and report, asking the founder to paste the job conclusions and annotation text. A missing run, a skipped job or an unreadable result is never green and does not count as a round trip. Cap: 3 round trips per plan unless the plan says otherwise. At the cap stop and report the failing steps, their annotations, every fix tried and the round trips used; the founder replies `extend <n>` or `stop`. An agent's claim of success is never evidence.

**Notices files.** A plan that records CI notices writes `.planning/phases/04-ub-detection-and-decision-log/04-NN-<JOB>-NOTICES.md` in the 02-22 layout: line 1 `# Plan 04-NN round trip <n>: <job> notices`, line 2 empty, line 3 `Run <run id> (<workflow file stem>), head <40-hex sha>, job <job id>, read from the job annotations with gh api (parts joined in order, final newline dropped as the workflow's annotate helper specifies).`, line 4 empty, then from line 5 one section per title, `## <title> (<n> annotation part(s))` followed by the text in a fenced block. GitHub keeps at most 10 annotations per level per step, so a notice of more than 9 parts is published by several steps; each job keeps at most 50 annotations, so the new `ub` job has its own budget (D-25).

**Housekeeping.** Keep build outputs in `target/`; if free disk drops below 1 GB delete `target/debug/incremental`; never delete `.mt-work/capture`. On a permission denial stop at once and quote it; never change permission settings and never retry a variant of the denied command. No model identifiers in commits, PR text, notices or SUMMARYs.

**Cut list (D-26).** If the phase runs long, cut in this order and log each cut with its reason in the phase summary: (1) trap UBSan on target, plan 04-14; (2) attempting KLEE beyond the floor of 3 targets, plan 04-13 Task 3. Nothing else is cut.
