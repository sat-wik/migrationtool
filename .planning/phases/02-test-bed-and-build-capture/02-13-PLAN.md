Close G-02-4 and fix review warning WR-07. The zip seed reader switches from flate2's zlib-rs backend to its rust_backend (miniz_oxide), and each archive gets a total decompressed-size budget (founder decision G-02-4). Before any new crate is built, the founder verifies every crate the switch adds to Cargo.lock (package legitimacy gate).

Purpose: untrusted fuzz archives are inflated by a decompressor that forbids unsafe code, and a small archive can no longer expand to gigabytes in memory.
Output: Cargo.toml and Cargo.lock on the new backend, zipsrc.rs with the budget, seeding.rs passing it, a new test file, updated call sites in the existing zip tests.
</objective>

Facts measured while planning (re-check them; do not trust them blindly):
- Workspace Cargo.toml line 35: `zip = { version = "=9.0.2", default-features = false, features = ["deflate-flate2-zlib-rs"] }`; Cargo.lock holds flate2 1.1.10 and zlib-rs 0.6.8. zip 9.0.2 offers `deflate-flate2` (flate2 with no backend chosen); flate2 1.1.10 offers `rust_backend` (miniz_oxide plus crc32fast). Without a backend flate2 does not compile, so mt-seeds must name flate2 itself to select rust_backend (feature unification).
- miniz_oxide's lib.rs has `#![forbid(unsafe_code)]`. flate2 1.1.10 has unsafe code in src/mem.rs and src/lib.rs (plus its C ffi modules, unused with rust_backend). zip 9.0.2 has unsafe code in src/format/blocks.rs (a Pod trait used to read headers) and src/datetime.rs. So the switch makes the inflater safe Rust; it does not make the whole zip path safe Rust.
- deny.toml allows MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, Zlib, Unicode-3.0.
- `zip_members(bytes, max_member_bytes)` reads members in archive order; a member over the limit by declared size is not read, others are read through `take(limit + 1)`; members are held in `ZipResult.members` and cloned into Candidates. Call sites: seeding.rs:365 and four in crates/mt-seeds/tests/build_03_seed_selection.rs.
- nanopb's tests/fuzztest/corpus.zip (1.07 MiB): 3672 members, 189 above 64 KiB by declared size, about 2.86 MB in the members within the limit; regressions.zip: 7 members, 6031 bytes.
- RESEARCH's Package Legitimacy Audit covers shlex, object and zip only. Any other crate entering Cargo.lock is unaudited, so it is treated as [ASSUMED] and needs the founder's check on its registry page (blocking, never auto-approvable, workflow.auto_advance ignored).
