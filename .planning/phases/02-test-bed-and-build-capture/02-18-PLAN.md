<objective>
Fix the second half of review warning WR-04 in the tool (founder decision: "replay must not trust artifacts that untrusted builds can write; give the containers separate writable dirs"). Capture splits into a build stage, which runs the upstream build and may write only its own run directory, and a record stage, which runs no upstream code and alone writes the artifacts replay and the determinism step read. Plan 02-19 then runs each build stage in its own container that mounts only that run directory writable.

Purpose: today the upstream build of a later target runs as the same user in the same container while earlier targets' capture.json and object copies are writable, and replay trusts them.
Output: capture_build, capture_record and BuildRecord in capture.rs; staged pipeline functions in testbed.rs; `--stage`, `--config` and `pairs` in mt-cli; tests.
</objective>

How capture works today (capture.rs): `capture(cfg, ctx, id, target, config)` builds a `Session` (fields cfg, ctx, layout, env with HOME and TMPDIR under the work dir, report, not_proven, build_failed, before) and runs `prepare` (verify_cached, record source and tools, remove and recreate run_root and capture_dir, create home and tmp, copy the cache tree to `src`, copy `testbed/targets/<id>` to `inputs` and hash it), `build` (Make: bear writing `raw_path()`; CMake: toolchain file at `toolchain_path()`, configure, the `before` listing, build, copy CMake's export to `raw_path()`), then `canonicalise`, `gates`, `check_entries` (probe in capture_dir), `configure_files` (CMake), the verdict, and writes capture.json. `raw_path()` and `toolchain_path()` are inside capture_dir today (capture.rs:303-317), which a build that may only write its run directory cannot reach, so they move to `<run_root>/stage/`. Plan 02-16 added `reported_tools`; plan 02-12 made configure_files use `before` for build-created archives; plan 02-11 put the entry probe's prefix in check_entry.

Trust model this plan implements (state it in the capture.rs module doc): upstream build code runs only in the build stage. The record stage reads the build's outputs (objects, the raw export, the CMake build directory) as untrusted data and checks them exactly as today. It takes from the build record only what describes the build itself: the build steps' run records, the not_proven and build_failed flags, and the `before` listing. Those can be falsified only by the same pair's own build, which could equally have built different objects, so they cannot alter another pair's evidence, the source verification, the tools, the inputs check or the replay comparison. Record this residual in the SUMMARY.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream build -> work directory | untrusted Makefiles and CMake scripts run as the container user |
| build stage -> record stage | the build record and the build's outputs cross from untrusted to trusted code |
