## GCC driver measurements (planning time; nothing was executed except where noted)

gcc.gnu.org and the gcc-mirror GitHub repository are blocked by this session's egress policy, so the set rests on measurements with the host's `arm-none-eabi-gcc` 13.2.1. The pinned image ships Arm GNU Toolchain 14.3.Rel1 (`container/pins.toml`). Most rows below use `arm-none-eabi-gcc -### -c t.c -o t.o <option>`, which prints the subcommands and runs none.

- `-wrapper /bin/echo,hi`: every subcommand (cc1, as) runs under /bin/echo.
- `-B<dir>/`, `-B <dir>/`, `--prefix=<dir>/`, `--prefix <dir>/`: with `<dir>/cc1` and `<dir>/as` present, the driver runs those instead of the pinned ones.
- `-specs=F`, `-specs F`, `--specs=F`, `--specs F`: all four read spec file F. Spec strings define the commands the driver runs (nano.specs renames `cpp_unique_options`).
- `-fplugin=<so>`, `-fplugin-arg-<p>-<k>=<v>`, `-iplugindir=<dir>`: passed to cc1. A real compile with `-fplugin=<missing>.so` fails with "cannot load plugin", so this build has plugin support.
- `@<file>` holding `-wrapper /bin/echo,viarsp`: subcommands run under /bin/echo. cc1 also expands `@file` itself: `-Wp,@<file>` with `-fplugin=<missing>.so` inside reached "cannot load plugin".
- `-Wp,-fplugin=<so>` and `-Xpreprocessor -fplugin=<so>`: `-fplugin=` reaches cc1. `-Wp,-B<dir>/` and `-Wp,-wrapper,/bin/echo` reach cc1 as arguments.
- `-fcompare-debug=-B<dir>/`: both compiles run `<dir>/cc1` and `<dir>/as`. `-fcompare-debug=-O2 -wrapper /bin/echo,cmp`: every subcommand runs under the wrapper. The driver parses the payload as driver options.
- Not refused, measured: `--sysroot=`, `--sysroot`, `-isysroot`, `-iprefix`, `--include-prefix=`, `-imultilib` and `-no-canonical-prefixes` leave cc1 and as the pinned programs. `-Wa,`, `-Xassembler` and `--for-assembler=` reach only GNU as. `-Wl,` and `--for-linker=` run nothing for `-c`. `-fuse-ld=/bin/sh` is unrecognised. `-foffload=nvptx-none` is refused by this toolchain (valid: default, disable). `-no-integrated-cpp`, `-save-temps`, `-time` and plain `-fcompare-debug` re-run only the pinned cc1 and as.
- GCC rejects abbreviated or doubled spellings: `--pref=`, `--spec=`, `--wrapper`, `-wrapper=` and `--fplugin=` are all "unrecognized command-line option". So there is no hidden spelling.
- Real use: 0 of the 29 canonical `compile_commands.json` in the local `.mt-work/capture` (2026-10-13) and 0 entries of the two committed CI fixtures use any refused option. The real flags are -D, -I, -O*, -W*, -c, -fPIC, -fstack-protector-strong, -fvisibility=, -g, -mcpu/-mthumb/-mfloat-abi/-mfpu, -o, -pedantic and -std=.
- Write paths (orchestrator amendment), measured the same way with `-c t.c -o out/t.o`:
  - `-MD` and `-MMD`, and their aliases `--write-dependencies` and `--write-user-dependencies`, take no operand. cc1 gets `-MD out/t.d`, derived from the output.
  - `-MF <p>` and `-MF<p>` give cc1 `-MF <p>`.
  - `-MT` and `-MQ`, separate or joined, are target names only.
  - `--output=<p>` and `--output <p>` make as write `<p>` and set the dump directory to the directory of `<p>`.
  - With `-o out/a.o -o out/b.o`, or `-o out/a.o --output=out/b.o`, a real compile writes only `out/b.o` (and `out/b.su`): the last output wins.
  - `-dumpdir <d>` and `--dumpdir <d>` set the dump directory; the `=` forms are rejected by the driver. `-dumpdir=dd/` is passed to cc1, which reads it as `-d` debugging letters ("unrecognized gcc debugging option: u, m, d").
  - `-dumpbase <p>` and `--dumpbase <p>`: a directory component in `<p>` replaces the dump directory.
  - `-dumpbase-ext .c` is a suffix name.
  - `-aux-info <p>` and `-aux-info=<p>` give cc1 `-aux-info <p>`. The joined form and `--aux-info` are rejected.
  - `-save-temps=obj` writes `out/t.i` and `out/t.s`. `-save-temps=<path>` is a fatal error; only `cwd` and `obj` are valid. `--save-temps=` is rejected.
  - `-fdump-tree-all=<p>`, `-fopt-info-vec=<p>` and `-fdump-final-insns=<p>` pass `<p>` to cc1.
  - `-fstack-usage` writes `out/t.su`, next to the output, in a real compile. `-fdiagnostics-format=sarif-file` and `-fdump-*` without a value use the same aux name.
  - Carriers:
    - `-Wp,-MD,<p>` gives cc1 `-MD <p>`; cc1's `-MD` takes a path.
    - `-Wp,-MF -Wp,<p>` and `-Xpreprocessor -MF -Xpreprocessor <p>` both give cc1 `-MF <p>`: the driver joins the operand across arguments.
    - `-Wa,-alh=<p>` gives as `-alh=<p>` (a listing file). `-Wa,--MD,<p>` gives as `--MD <p>`.
    - `-Xassembler -o -Xassembler <p>` gives as a second `-o <p>`.
    - `--for-assembler=<x>` and `--for-assembler <x>` pass `<x>` to as.
  - Local captures: 29 canonical files under `.mt-work/capture/<id>/<cfg>/`, with directories under `/home/user/migrationtool/.mt-work/run/<id>/<cfg>`, so the run root is `<capture dir>/../run/<id>/<cfg>`. argv[0] is the scratchpad Arm GCC 14.3 of an earlier session. Each `compile_commands.raw.json` sits next to its canonical file.
- Host probes for the tests, run for real with host gcc 13.3: `cc -wrapper <script> -c t.c` creates the script's marker (the script writes a marker, then execs its arguments). `cc -B<dir>/ -c t.c`, with `<dir>/cc1` a script that writes the marker and exits 1, creates the marker.
