## CI round trip (testbed, full bed)

Protocol as in plan 02-06 (executor-pushes on the session branch only; `testbed` and `ci` awaited; annotations via `gh api`). The full bed is about 31 pairs and 500 translation units; expect 10-15 minutes per run (A7); the workflow keeps `timeout-minutes: 45`. At most 6 full-bed round trips in Task 3, then a checkpoint:human-action quoting every still-failing pair and the fixes tried.

Pre-decided handling (record each in the SUMMARY):
- A failing target or configuration gets exactly one documented fix attempt, made only in its manifest data or its committed inputs: add a missing define, add `-ffile-prefix-map={src}=/mt` to the configuration's cflags (it then appears in both builds because replay runs the captured argv), add `-Wno-error` where a `-Werror` Makefile trips a GCC 14.3 warning (Pitfall 19), or pass a documented build option. Never relax a gate, the normalisation rule or the comparison.
- Still failing: add a drop-log entry with the cause from the report (`fetch_failed`, `build_failed`, `capture_failed`, `differs`, `not_proven`, `entry_mismatch`), the differing objects and sections, the fix tried and the CI run id; a failing `default` configuration drops the target; a failing variant drops the variant when `drop_granularity: variant`, else the target.
- An entry signature that differs only because clang 16 prints it differently (A4) is fixed as data, as in the tracer, not dropped.
- A variant whose capture shows `changes_code false` is dropped as a variant with cause `variant_no_code_change` under either granularity (D-05 says a variant must change compiled code; the target keeps its default).
- If fewer than 10 targets would remain, stop with a checkpoint:human-action: the phase fails by D-11, and a backup swap-in is a deferred idea that only the founder can reopen.
