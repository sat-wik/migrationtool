2. `SHA=$(git rev-parse HEAD)`; list runs with `gh api "repos/sat-wik/migrationtool/actions/runs?head_sha=${SHA}&per_page=50" --jq '.workflow_runs[] | [.id, .path, .status, .conclusion] | @tsv'`.
3. Poll every 60 s (background loop or repeated calls; one Bash call is limited to 10 minutes) until each expected run is `completed`. A run still going after its `timeout-minutes` plus 15 minutes is stuck: checkpoint:human-action.
4. Jobs: `gh api repos/sat-wik/migrationtool/actions/runs/<run_id>/jobs --jq '.jobs[] | [.id, .name, .conclusion] | @tsv'`.
5. Annotations: `gh api --paginate repos/sat-wik/migrationtool/check-runs/<job_id>/annotations --jq '.[] | "== " + .title + "\n" + .message'`.
6. Any `gh api` failure: checkpoint:human-action asking the founder to paste job conclusions and annotation text. A missing run, a skipped job or an unreadable result is never green.

## CI budget (phase-wide, binding)

A round trip is one push of the session branch plus waiting for and reading the runs it triggers. Every CI task may spend at most 3 round trips, its planned ones included. The phase plans 9 round trips and one PR-check wait; without a founder extension it can spend at most 18.

| Plan | Task | Awaited runs | Planned | Cap |
|------|------|--------------|---------|-----|
| 02-01 | Task 1 | pin-discovery (ci fails one named test) | 1 (RT1) | 3 |
| 02-01 | Task 3 | container, ci, pin-discovery | 2 (RT2, RT3) | 3 |
| 02-02 | Task 1 | PR checks container and ci (a wait, no push) | 1 wait | 1 wait |
| 02-06 | Tracer | testbed, ci | 1 | 3 |
| 02-06 | Task 2 | testbed | 1 | 3 |
| 02-08 | Task 3 | testbed | 1 | 3 |

| 02-03, 02-04, 02-05, 02-07, 02-10 | all | none (offline, no push) | 0 | 0 |

Escalation: when a task's last allowed round trip is not green, stop with a checkpoint:decision that quotes the failing jobs or steps, their annotations, every fix tried and the round trips used. The founder replies `extend <n>` (n more round trips, recorded in the SUMMARY as a budget extension) or `stop` (the plan ends unfinished and the SUMMARY says why); never push past the cap without that reply. Plan 02-09 adds a drop option to this checkpoint (its context section). Every SUMMARY records the round trips its plan used. A `gh api` failure is still a checkpoint:human-action (protocol step 6) and does not count as a round trip.

Pre-decided fallbacks (apply without asking, record each as a deviation):
- A1: a package name has no candidate at the snapshot: stop with checkpoint:human-action quoting the annotation; never invent a version.
- A5-style: a captured version output differs from the planned regex or arguments (for example bzip2 prints its banner only for `--help`, on stderr, or exits non-zero): fix `version_args` or `version_regex` in container/pins.toml and the fixtures (data, not code), and keep `expect` equal to `upstream_version` of the apt pin.
- A package pulls an LLVM-family dependency that trips the llvm_packages row: stop with checkpoint:decision quoting the dpkg list; never install a second LLVM (P1 D-02).
