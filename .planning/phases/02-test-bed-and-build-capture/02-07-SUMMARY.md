# Phase 2 Plan 07: Seed Extraction Library Summary

**`mt-seeds` crate: a linear C/C++ lexer (exact C escape rules) for byte arrays and string literals, hex-text and in-memory zip readers, deterministic round-robin selection under the D-16 caps, and a sha256-named corpus with a versioned `index.json` plus a file-by-file drift checker.**

## Accomplishments

- Lexer (`lexer.rs`): one tokenizer pass plus a linear scan. Skips comments and preprocessor lines (keeps `#define` bodies, with a barrier so an unbalanced body cannot leak), ignores braces and comment markers inside string and character literals, tracks 1-based start lines through splices, block comments and CRLF. Byte arrays: innermost groups of integer/character literals in 0..=255 with the allowed casts and suffixes. Strings: adjacent-literal concatenation, greedy `\x`, up-to-3-digit octal, simple escapes, unknown escape rejects, prefixed and raw literals skipped and counted.
- `hex.rs`, `zipsrc.rs`: hex-text decoding, and zip members in archive order with `enclosed_name()`, a declared-size check plus a `take(max + 1)` bounded read, and no path ever built from a member name.
- `select.rs`: total content-based ordering (method rank, path bytes, line, member, bytes), grouping by (method, path), round-robin walk, inclusive caps, duplicate/too_large/over_cap/unsupported counts.
- `index.rs`: `SeedIndex` (schema_version 1, seeds sorted by sha256, no clock field), `write_corpus` (seed files + `index.json` + `NOTICE`, nothing else) and `check_corpus` (`added`/`missing`/`changed` lines ordered by name).

## Interface for plan 02-08

- `mt_seeds::Method` (serde snake_case, `Ord` = selection rank), `SeedError`, `sha256_hex(&[u8]) -> String`.
- `lexer::{c_byte_arrays, c_string_literals}<S: AsRef<[u8]> + ?Sized>(&S) -> LexResult { found: Vec<Extracted { bytes, line }>, unsupported }`.
- `hex::decode_hex_text(&str) -> Result<Vec<u8>, SeedError>`.
- `zipsrc::zip_members(&[u8], max_member_bytes: u64) -> Result<ZipResult { members: Vec<ZipMember { name, bytes }>, unsupported, too_large }, SeedError>`.
- `select::select(Vec<Candidate>, &Caps, unsupported: u64) -> Selection`; `Caps` (all `u64`, `Default` = 200 / 1 MiB / 64 KiB), `Skipped` (`Copy`), `SourceRef { path, line: Option<u32>, member: Option<String> }`.
- `index::SeedIndex::from_selection(&str target, &str commit, IndexLicence, Caps, &Selection)`, `.to_json() -> Result<String, SeedError>`, `write_corpus(&Path, &SeedIndex, &Selection, &str notice)`, `check_corpus(...) -> Result<Vec<String>, SeedError>`. `IndexLicence.elected` is `Option<String>`.
- The caller must add `ZipResult::unsupported` and `LexResult::unsupported` (and any file it skips, for example above 8 MiB) into the `unsupported` argument of `select`, and turn `ZipResult::too_large` into the same count it wants reported (the index has no separate zip counter; `select` only counts candidates it is given).

## Decisions Made

- Lexer extras beyond the plan text, all in the direction of fewer false seeds: a group containing `;` is a statement block (not counted unsupported); `extern "C"` linkage strings are ignored; an empty `{}` is neither a seed nor unsupported; octal escapes above 255 (`\400`) reject the literal as `\x` does; conditionals (`#if`) are not evaluated, so data in an inactive branch is still found.
- A run of adjacent literals that contains a prefixed, raw or rejected literal is counted once as unsupported (the whole run is dropped, since a partial concatenation would be wrong bytes).
- Hex text: digits of all tokens join before pairing (so `de ad\nbe ef` is four bytes), but a `0x`-prefixed token stands for one value and must itself have an even digit count.
- Zip member order inside an archive is by member name after selection (the order must not depend on input order); archive order is still what `zip_members` returns.
- `write_corpus` deletes regular files and symlinks only and refuses a directory that contains a subdirectory; it also verifies index and selection agree (sha256 matches content, same seed set and lengths) before changing anything.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] zip deflate feature named in the research does not build**
- **Found during:** Task 2 (adding the dependency)
- **Issue:** RESEARCH used `deflate-flate2`, but that feature enables `flate2` with no backend, so flate2 fails with "No compression backend selected" and `crc32fast` unresolved.
- **Fix:** Use `deflate-flate2-zlib-rs` (printed by `cargo info zip@9.0.2`), still the single deflate feature and pure Rust (zlib-rs). Resulting tree adds only crc32fast, flate2, zlib-rs, indexmap (hashbrown, equivalent), memchr and typed-path. The alternative is the `flate2` default `rust_backend` (miniz_oxide) via a direct flate2 dependency; not chosen to keep one new dependency line. Reconsider if an all-safe-Rust decompressor is wanted for untrusted archives.
- **Files modified:** Cargo.toml, Cargo.lock
- **Verification:** `cargo build`, `cargo deny check` (all four checks ok), workspace tests
- **Committed in:** c413ca2

**2. [Rule 2 - Missing critical] Stricter zip member name check than `enclosed_name()` alone**
- **Found during:** Task 2 (the absolute-name test case)
- **Issue:** In zip 9.0.2 `enclosed_name()` returns a relative path for an absolute name (`/tmp/x/pwned` becomes `tmp/x/pwned`) and folds `x/../y` into `y`. Used alone, this records a misleading provenance name and lets two members collapse onto one name, contrary to the plan's "names only via enclosed_name, absolute names not enclosed" intent.
- **Fix:** After `enclosed_name()`, require the `/`-joined enclosed form to equal the stored name; otherwise count the member unsupported. Tests cover `../evil`, an absolute path and `x/../y`.
- **Files modified:** crates/mt-seeds/src/zipsrc.rs, crates/mt-seeds/tests/build_03_seed_selection.rs
- **Verification:** `build_03_zip_members_are_read_without_touching_disk`
- **Committed in:** 8ade9c4

**3. [Rule 1 - Bug] clippy rejected the first hex decoder**
- **Found during:** Task 1 (verification)
- **Issue:** `% 2 != 0` and `chunks_exact(2)` fail `-D warnings` under Rust 1.99 clippy.
- **Fix:** `is_multiple_of(2)` and `as_chunks::<2>()`.
- **Files modified:** crates/mt-seeds/src/hex.rs
- **Committed in:** d37d634
