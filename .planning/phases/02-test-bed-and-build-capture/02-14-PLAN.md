<objective>
Fix review warning WR-05 (the founder asked for it in this gap closure; it has no UAT gap id). The workflow's determinism step compares two captures with `jq -S ... | cmp -s`, which reports "identical" when jq fails on both files. This plan adds the comparison to mt itself, in Rust, failing closed on every unreadable, empty or missing file; plan 02-17 switches the workflow step to it.

Purpose: the determinism evidence can no longer pass because a report was truncated or invalid.
Output: module `mt_capture::compare`, subcommand `mt testbed compare`, tests.
</objective>

What the workflow does today (testbed.yml lines 354-421, the step "Capture again and compare the reports (determinism)"): it lists the files under `/out/capture` and `/out/capture-rerun/capture`, requires equal lists, compares `*.compile_commands.json` with `cmp -s`, and compares every other file through `norm()`, a jq filter that, for reports with `kind == "capture"`, deletes `.run.stdout.sha256`, `.bytes_total` and `.bytes_stored` from every step named `cmake configure` or starting with `clang ast `, then sorts keys. It fails when problems were found, the rerun exited non-zero, or zero files were compared. WR-05: jq failing on both sides gives two empty outputs, `cmp -s` calls them equal, and an empty file is never flagged.

The new comparator keeps exactly those semantics and closes the fail-open paths. Files under the capture output tree are `<id>/<config>.json` (capture reports), `<id>/<config>.compile_commands.json` and `<id>/variant.json`. The committed CI capture report `crates/mt-capture/tests/fixtures/ci/corejson-default.capture.json` holds a real `cmake configure` step and is the realistic test input.

mt-cli conventions (main.rs): `TestbedAction` variants document the exit contract; `testbed_command` returns `Result<bool>` mapped to exit 0/1, errors print `error: {err:#}` and exit 2; mt-cli only parses arguments. `#![forbid(unsafe_code)]`, thiserror in mt-capture, anyhow only in mt-cli, no unwrap or expect outside tests.
