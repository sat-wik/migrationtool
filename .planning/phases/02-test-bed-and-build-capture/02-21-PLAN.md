## Founder decisions (G-02-8 in 02-UAT.md, binding)

1. Replace the deny-list gate with an allow-list gate built on one operand-aware argument walk. The walk knows which options take a separate operand, so an operand is never read as an option. The same walk serves the `-c` test, `derive_output` and the write-path check, at capture (record stage) and at replay.
2. The allow-list is measured from the 30 retained pairs' recorded compile commands and committed as a code constant with a comment that says how it was measured. Also allowed:
   - the depfile flags `-MD`, `-MMD`, `-MF`, `-MT`, `-MQ` and `-MP`, with every path under the run root;
   - `-specs=<name>`, only for names the pinned toolchain ships (WR-13). The set is derived from the pinned toolchain image or from recorded evidence, with no network beyond what CI already does. It cannot be derived offline here (see the measurements), so it is measured in CI and committed.

   - every long `--<name>` spelling;
   - any `-Wa,`, `-Xassembler`, `-Wl,`, `-Xlinker`, `-Wp,` or `-Xpreprocessor` piece that is not on the allow-list. None is measured, so every carrier is refused;
   - `@file` response files.
4. WR-12: the toolchain check must also prove what configure read (a configure-time check), not only the end state.
5. WR-14: an unreadable toolchain file is a named cause on the pair (a row), not an aborted step.

## Claude's discretion (planner choices; record each in the SUMMARY)

Cause taxonomy. The allow-list decides; no list of known-bad options is kept for naming. Table: refusal, then `CcError`, then cause token.
- empty argv: `NotCompileOnly`, `not_compile_only` (unchanged)
- argv[0] not allow-listed: `CompilerNotAllowed`, `compiler_not_allowed` (unchanged)
- any argument after argv[0] that starts with `@`, operand or not: `HelperOption { flag }`, `helper_option` (kept: the driver reads options from a file)
- `-specs=<name>` with a name not in `SHIPPED_SPECS`, empty, or containing `/`, and every other argument that starts with `-specs`: `HelperOption { flag }`, `helper_option` (kept: the driver reads commands from a spec file)
- `-flto*` and `-fprofile-*` options: `ForbiddenFlag { flag }`, `forbidden_flag` (unchanged; regression guard)
- any other argument that starts with `-` and is not on the allow-list (every `--<name>`, every carrier, `-wrapper`, `-B`, `-fplugin*`, `-include`, `-x`, `-dumpdir`, and so on): new `OptionNotAllowed { flag }`, new token `option_not_allowed`
- trailing `-o`: `DanglingOutput`, `dangling_output` (unchanged; regression guard)
- trailing `-MF`, `-MT` or `-MQ`: `WriteRedirect { flag }`, `write_redirect` (kept: an unboundable depfile)
- trailing `-I`: `OptionNotAllowed { flag: "-I" }`, `option_not_allowed`
- an `-o` or `-MF` operand that resolves (lexically, against the entry's directory) outside the run root, or a directory or derived output outside it: `OutsideRunRoot { path }`, `outside_run_root` (unchanged)
- no top-level `-c` after a complete walk: `NotCompileOnly`, `not_compile_only`
- an unreadable run-directory file the record stage needs (WR-14): new token `run_dir_unreadable`

Consequence: options that 02-20 named `helper_option` or `write_redirect` because of a family prefix now read `option_not_allowed`, for example `-wrapper`, `-B`, `-fplugin=`, `--output=` and `-Wp,-MD,...`. The 02-20 tests keep their names, because 02-SECURITY.md cites them, and change their expected variants.

Names: `ALLOWED_OPTIONS` (a table of `AllowedOption { spelling, operand }`; `Operand` tells whether there is no operand, a joined-or-separate operand or a joined-only operand, and what the operand is: output path, depfile path, target name, include directory, macro or spec name), `SHIPPED_SPECS`, `CommandWalk { compile_only, outputs, dep_files }`, `walk_arguments`, `CcPolicy::check_command`, `toolchain_file_finding`, `configured_toolchain_findings`.
