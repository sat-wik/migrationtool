The isotp failure (02-09 SUMMARY, testbed run 38387515333): isotp.c starts with `#include <stdint.h>`, `#include "assert.h"`, `#include "isotp.h"`. isotp.h includes <stdint.h> only under `__cplusplus`, so a probe holding only `#include "<abs>/isotp.h"` fails on `uint8_t`. There is no assert.h in the isotp tree; the compiler resolves it in the system headers. The CMake recipe adds `-I<src>/`.

Existing API (02-05): `probe_source(header_abs)`, `filter_flags(arguments)`, `clang_ast_argv`, `clang_deps_argv`, `check_entry(cfg, tools, layout, env, canonical, entry) -> Result<EntryCheck, EntryError>`, `EntryResult { found, signature_matches, header_included, found_signature, detail }`. `check_entry` resolves the defining unit by `lexical(layout.src.join(entry.source))`, writes the probe to `layout.capture_dir/entry_probe.c`, runs clang with the unit's filtered flags in the unit's `directory`. Test helpers: `crates/mt-capture/tests/support/mod.rs` (`make_upstream`, `git_target`, `local_arm_tools`, `capture_context`); `bed_01_entry_mismatch_fails_the_capture` in `bed_01_entries.rs` shows a capture-level entry test.
