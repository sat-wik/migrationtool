Container design (Docker facts the design relies on): bind mounts nested inside another bind mount get their mount points created inside the outer host directory, so mounting a fresh empty host directory at /work and then the cache and the pair's run directory below it needs no write to the read-only root. Files the fetch container wrote are owned by uid 65534; mounting the original cache read-only (never copying it on the host) keeps that owner, so git inside the containers sees no "dubious ownership". Host directories the containers write must be created by the step and made mode 0777 (RESEARCH Pitfall 15). RUNNER_TEMP is fresh per job, so a run directory that already exists is an error, not something to delete.
