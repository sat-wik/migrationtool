Schema added here: `[seed_caps] { max_seeds, max_total_bytes, max_seed_bytes }` (required); per target `seed_source: Vec<SeedSource>` (TOML `[[target.<id>.seed_source]]`, may be empty) with `SeedSource { path, methods: Vec<String> (subset of file_copy, hex_text, c_array, c_string, zip_member), extensions: Option<Vec<String>> (empty string matches files without an extension), entries: Vec<String> (entry names of the target; empty means all) }`. Hand-made inputs: every `*.hex` under `testbed/targets/<id>/hand-made/`. Module `mt_capture::seeding` with `run_seeds(opts, seeds_dir, check) -> Result<StepSummary, TestbedError>` and the testable inner `seed_target(tree, commit, target, hand_made_dir, caps) -> Result<(SeedIndex, Selection), SeedingError>`.

Fetching trees in this Docker-less session: cloud sessions have no Docker, and outbound HTTPS needs the session proxy, which the runner deliberately strips from child environments. So for seed extraction only, the executor fills `.mt-work/cache/<id>/<commit>/tree` with plain git in the shell, using exactly the commands of `fetch.rs` (git init, fetch --depth 1 --no-tags --no-recurse-submodules <url> <commit>, checkout --detach FETCH_HEAD), and for mbedtls downloads the pinned archive to `archive.tar.bz2`, checks its sha256 and extracts it with --strip-components=1. It then runs `mt testbed fetch --all` with the container pins, whose cache-hit path verifies every commit, archive sha256 and tree sha256 without network. A tree that fails verification is never used. CI's `seeds --check` then regenerates from container-fetched trees (D-19), which is the proof that the committed seeds come from the pinned sources.

Directories in files_modified: `testbed/targets/` holds one `<id>/hand-made/` directory per target that needs hand-made seeds, `research/testbed-seeds/` holds README.md and the `<id>.py` helpers, and `testbed/seeds/` holds one `<id>/` corpus per target; the ids are known only after extraction from the approved list, so the directories are listed instead of per-target paths.
