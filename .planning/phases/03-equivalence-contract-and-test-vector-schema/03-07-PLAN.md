## Claude's discretion settled here (record each in the SUMMARY)

- Manifest additions (additive, no schema bump; each `skip_serializing_if` empty):
  - `[[target.X.entry.local]]`: `name` (C identifier, unique across roles and locals, not reserved), `type` (closed type grammar below), optional `count` (1 to 64). Recorded in lib_state like a state.
  - `[[target.X.entry.setup]]`: exactly one of `call` (C identifier) with `args` (list) and `expect` (decimal integer string or `void`), or `set` (`<local>.<member>(.<member>)*`) with `value`.
  - `SetupArg` grammar: `$in`, `$len`, `$cap` (the out buffer capacity), `$arg:<scalar name>`, a decimal integer (optionally negative), `&<state or local name>` (its address), `<local name>` (its value, for a pointer local). `set` values: `$in`, `$in+<n>`, `$len`, `$len-<n>`, a decimal integer.
  - `Role::Wrap` with `ptr_field` and `len_field` (C identifiers): a struct passed by value, built from the input pointer and length; the wrapped entry keeps `accepted_wrapped = true`.
  - `ArgRole.count` on `state` (1 to 64): an array of the pointee type.
  - Closed type grammar for every type text that reaches generated C (the pointee of a state or out role, a local's type, a wrap's type, a struct return): `^(const )?(struct |union |enum )?[A-Za-z_][A-Za-z0-9_]*( \*)?$`, applied after the one-level pointer strip; anything else is `not_expressible` at build time. Scalars are passed without a cast (C's implicit integer-to-enum conversion), so no scalar type text is pasted.
- Frame: a status word distinguishes "entry ran" from "setup step k returned r"; the runtime stops at the first mismatch and still dumps every region.
- Outcome `setup_failed`: stderr `outcome=setup_failed step=<k>`; rc is the step's return value; lib_state_in and lib_state_out both hold the state at the stop; no label; compared (it is defined behavior of the setup call on that input).
- Roles (each with a comment naming D-12):
  - httpparser `http_parser_execute (http_parser *, const http_parser_settings *, const char *, size_t)`: state `parser`, state `settings`, in_buf, in_len; setup `call = "http_parser_init"`, `args = ["&parser", "2"]` (HTTP_BOTH), `expect = "void"`.
  - tinycbor `cbor_value_validate (const CborValue *, uint32_t)`: state `it`, scalar `flags` (`default = 0`, a sweep with the strict-validation flag value from cbor.h written as a decimal with a comment naming the constant); local `parser` of type `CborParser`; setup `call = "cbor_parser_init"`, `args = ["$in", "$len", "0", "&parser", "&it"]`, `expect = "0"`. The input buffer is not a parameter of the entry, so the input is a role-less region declared by the setup's `$in`; argv carries the scalar `flags` only, and `$len` is the stdin length.
  - qcbor `QCBORDecode_Init (QCBORDecodeContext *, UsefulBufC, QCBORDecodeMode)`: state `ctx`, wrap `buf` (`ptr_field = "ptr"`, `len_field = "len"`), scalar `mode` (`default = 0`, `sweep = [1, 2]`).
  - zcbor `zcbor_new_decode_state (zcbor_state_t *, size_t, const uint8_t *, size_t, size_t, uint8_t *, size_t)`: state `states` with `count = 3`, scalar `n_states` (`default = 3`; a comment says it must equal the count), in_buf, in_len, scalar `elem_count` (`default = 1`), out_buf, out_cap (`default = 0`, `sweep = [64]`).
- An entry whose only use of the input is through `$in` in a setup step (tinycbor validate) is valid: the validator requires the input to be reached either by an `in_buf` or `wrap` role or by a setup argument.
