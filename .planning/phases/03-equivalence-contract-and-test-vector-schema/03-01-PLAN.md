## Claude's discretion settled here (record each in the SUMMARY)

- Crate split: the executor lives in a new `mt-harness` crate (the name `docs/guidelines/building-the-tool.md` section 3 reserves for the differential runner and emulator replay, so Phase 5 reuses it). It depends on `mt-toolchain` now; plan 03-04 adds `mt-capture`, `mt-vectors`, `mt-contract`, `mt-seeds` and `object`.
- Budgets are constants in `crates/mt-harness/src/budget.rs`, `Budgets::DEFAULT`, recorded in every provenance record later (D-19): `timeout_ms = 10000`, `reserved_va = 0x1000_0000` (256 MiB, also the memory budget), `heap_arena = 1 MiB` (the `_sbrk` arena), `sentinel = 0xA5` (output prefill, D-07), `slack_fill = 0x5A` (guard slack pattern), `max_input = 65536` (the manifest's `max_seed_bytes`). They are not manifest keys.
- `has_ub` labels written by the executor: `crash:SIGSEGV`, `crash:SIGBUS`, `crash:SIGILL`, `crash:SIGFPE`, `crash:SIGABRT`, `oob-write:guard-slack`, `timeout`. A timeout gets a label so TRACTOR tools and the comparison rule skip it (D-02 "never a pass"); its `rc` is -9, the signal the runner kills with. List this in the SUMMARY as a choice the founder may revisit.
- Driver exit codes reserved for the driver's own failures: 95 (the C code called `exit`), 96 (request file open or read failed), 97 (malformed request), 98 (`mmap` failed, which includes a mapping beyond `-R`), 99 (any other driver setup failure). All are `executor_error`.
- The result frame: little-endian, magic `MTRS`, version 1, a status word, the raw return value, the count of bytes the C code wrote through libc (discarded by the `_write` stub, never mixed into the frame), the slack check result, then a length-prefixed region table, then the end marker `MTRE`. Later plans add regions (output buffer, state objects, globals) without a new frame version. The request file `req.bin`: magic `MTRQ`, version 1, then length-prefixed fields; the self-test uses the case selector and the input bytes.
- The template has a closed set of placeholders written `@MT_<NAME>@`. The renderer replaces each exactly once and fails on any other `@MT_` token or a leftover. Plan 03-04 adds the generated entry-call placeholders.
- D-02's "empty, fixed environment" is implemented as the runner's fixed four-key base (`LANG`, `PATH`, `SOURCE_DATE_EPOCH`, `TZ`, values from the pins) with no extra variable: the audited runner cannot start a child with fewer, QEMU passes those four to the guest, and the driver moves `sp` to its own mapping so nothing in the guest depends on them. The contract (plan 03-02) states it this way. List it in the SUMMARY as an interpretation for the founder.
- The `pins.toml` comment "user mode cannot run bare-metal Cortex-M images" is not edited (it would touch the image inputs). Plan 03-02's contract states the distinction: unmodified firmware cannot run in user mode, the hosted-style driver can.

## Measurements at planning time (research, this host, QEMU 8.2.2 / GCC 13.2.1; the image differs)

- A static ELF with a Thumb `_start` and `svc #0` syscalls (`r7` = number: read 3, write 4, open 5, close 6, mprotect 125, rt_sigaction 174, sigaltstack 186, mmap2 192, exit_group 248) ran under `-cpu cortex-m4`; the `rt_sigaction` sigsetsize argument must be 8.
- Guard overrun by one byte gave SIGSEGV; the in-guest handler with `SA_ONSTACK` and `sigaltstack` exited 139 and left no `qemu_*.core` file; without it QEMU dies with signal 11 and may write a core file into the cwd.
- `-R 0x04000000` made a mapping at 0x08000000 fail and the driver exit 98. 100 runs gave one result hash, about 5 ms each.
- `--specs=linux.specs` crashed at startup: do not use it. `-nostartfiles --specs=nosys.specs` with `_init`/`_fini`, `_sbrk` over a static arena and the `_kill`/`_getpid` stubs linked and ran; `__libc_init_array` runs before the call.
- GCC arm-none-eabi uses 1-byte enums (`Tag_ABI_enum_size: small`); clang for `thumbv7em-none-eabihf` uses 4.
