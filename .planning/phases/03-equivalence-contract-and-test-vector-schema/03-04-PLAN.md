## Claude's discretion settled here (record each in the SUMMARY)

- Manifest shape (additive; `#[serde(default, skip_serializing_if = "Vec::is_empty")]` so entries without roles serialize as before):

  `[[target.corejson.entry.arg]]` then `role = "in_buf"`, and a second table with `role = "in_len"`.

  `ArgRole { role: Role, name: Option<String>, default: Option<i64>, sweep: Vec<i64>, max: Option<u64> }` with `deny_unknown_fields`; `Role` lowercase snake-case enum `in_buf | in_len | out_buf | out_cap | scalar` (later plans add variants). `in_buf` and `out_buf` take no name (their regions are `in` and `out`); `scalar` needs a C-identifier `name` not in `["in", "out", "globals", "heap", "ret"]`; `out_cap` and `scalar` need `default`; `in_len` takes optional `max` and needs it when the parameter's type text is one of `uint8_t`, `int8_t`, `unsigned char`, `char`, `signed char`, `uint16_t`, `int16_t`, `unsigned short`, `short`; values are decimal integers only (no constant names, so nothing but digits enters argv or C).
- `split_parameters(signature) -> Result<(String, Vec<String>), ManifestError>`: the return type text and the top-level parameter texts of the clang `qualType` string, splitting on commas outside parentheses; `(void)` is zero parameters. A pointer parameter is one whose text contains `*` at top level.
- Combinations: the product, in parameter order, of `[default] + sweep` for each `out_cap` and `scalar`; at most `MAX_SCALAR_COMBOS = 16`, checked by the validator.
- Initial roles (each value with a comment in the manifest naming D-11, D-14):
  - corejson `JSON_Validate (const char *, size_t)`: in_buf, in_len.
  - libfdt `fdt_check_full (const void *, size_t)`: in_buf, in_len.
  - lz4 `LZ4_decompress_safe (const char *, char *, int, int)`: in_buf, out_buf, in_len, out_cap with `default = 256` and `sweep = [16, 4096]` (a small capacity exercises the error path with partial writes, D-07; the executor may change the values with a recorded reason).
- Driver flags: `driver_flags(tu_arguments) -> Result<Vec<String>, AdapterError>` keeps `-I`, `-isystem`, `-iquote`, `-include`, `-D`, `-U` (with their operands) and the ABI-affecting flags `-fshort-enums`, `-fno-short-enums`, `-funsigned-char`, `-fsigned-char`, `-fshort-wchar`, `-fpack-struct*`; drops argv[0], the source, `-o` and its operand, `-c`, `-O*`, `-g*`, `-W*`, `-std=*`, `-M*` depfile options and their operands, `-fPIC`, `-fpic`, `-fstack-protector*`, `-fvisibility=*`, `-ffunction-sections`, `-fdata-sections`, `-pedantic`; the driver always adds the manifest baseline flags and `-std=gnu11`; any other `-f` or `-m` option is the error `unhandled_flag` naming it (fail closed). Measured local flags: the four baseline `-m` flags, `-fPIC`, `-std=c89`, `-fstack-protector-strong`, `-fvisibility=hidden`.
- The driver includes the entry's header through Phase 2's probe builder (`mt_capture::entries::unit_include_prefix` on the defining TU and `probe_source_with_prefix`), so the defining TU's include and define prefix is reproduced exactly or the header alone is used, and paths are checked the way Phase 2 checks them.
- Build artifacts per (target, config, entry) under `<work>/vectors-build/<target>/<config>/<entry>/`: `driver.c`, `pair.a`, `driver.elf`, `build.json` (object hashes, archive, driver source and ELF hashes, the build steps' run records, the global dump plan). `mt vectors run` recomputes the driver ELF's sha256 against build.json before any run.
- The corpus goes to `<corpus-dir>/<target>/<config>/<entry>/` (default `<work>/vectors`); the run's scratch slots go to `--scratch-dir` (default `<work>/tmp/vectors-slots`; `/tmp/mt-slots` in CI).
- Globals: `writable_globals` reads each captured object with `object` (defined data symbols of non-zero size in sections whose names start `.data` or `.bss`), and `locate_globals` joins them with the linked driver's symbol table (a local symbol is joined through the preceding `STT_FILE` entry; an ambiguous join is an error). Only globals present in the linked image are dumped. The initial bytes come from the ELF's section data (zero for `.bss`). A changed global needs the LayoutModel of plan 03-05; until a type is available the change is `untyped_global_changed` and the run fails. Locally, corejson and lz4 have no writable global and libfdt has `fdt_errtable` (80 bytes, never written).
- Output rows (fixed order: target, config, entry): build `<t>/<c>/<e> built driver_sha256=<hex>`, or `<t>/<c>/<e> link_unresolved (<names>)`, `<t>/<c>/<e> unhandled_flag (<flag>)`, `<t>/<c>/<e> no_roles`; run `<t>/<c>/<e> vectors=<n> ok=<n> fault=<n> abort=<n> timeout=<n> setup_failed=<n> skipped=<n> twice=identical`; replay `<corpus dir> identical <n>` or `<corpus dir> differs <sha256>`; check `identical <n> files` or the first difference; every command ends with `result: passed (<n> rows)` or `result: failed`.
- `run_guest NAME ARGS...`: the same flags and read-only mounts as `run_vectors`, but `/work` read-only, the one writable mount `$RUNNER_TEMP/out/NAME` at `/vectors`, `--tmpfs /tmp` for the slots, then `mt vectors ARGS...`. Captured object code runs only here.

## Pre-decided handling (apply without asking; record each as a deviation)

- A pair's objects fail `verify_objects` in CI, or its replay report is not identical: the Phase 2 evidence is not what the executor may link. Stop and report the pair; never relax the check.
- `unhandled_flag` on a real compile command in CI: classify the flag against GCC 14.3's documentation of ABI effects; add it to the kept list only if it changes ABI or layout, to the dropped list only if it provably does not, each with a test row; otherwise stop and report.
- A link fails on unresolved symbols for one of this plan's three entries: report the names; the template gains only libc or libgcc-level stubs (never a stub of a target function); if a target symbol is missing, stop and report (03-06's drop log will carry it).
- Two runs of one vector differ: never retry, never exclude a field. Investigate once (uninitialised driver memory, environment, addresses), fix the driver or template, test-first; if the C itself is nondeterministic, stop and report the seed.
- `untyped_global_changed` on one of this plan's entries: the global is real state; stop and report the global and the seed (plan 03-05 brings typing; do not store raw bytes).
- `arm-none-eabi-ar` was reported missing by plan 03-01's self-test: use `/usr/lib/llvm-16/bin/llvm-ar` with the same `qcsD` modifiers, recorded as a deviation.
- A Phase 2 testbed-* notice differs from 02-22-CI-NOTICES.md from line 5 on: stop and report.
