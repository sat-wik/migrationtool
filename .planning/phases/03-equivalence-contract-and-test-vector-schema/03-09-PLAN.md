## Claude's discretion settled here (record each in the SUMMARY)

- **Source:** bookworm-backports at the pinned `snapshot_timestamp` (`20261005T000000Z`), the same timestamp main, updates and security use. No new pin key and no change to `mt-toolchain` code. A different backports timestamp would need a new `[image]` key and code in pins.rs, build_args.rs and manifest.rs; that is out of this plan (see the version rule).
- **Selection:** an apt preferences file in stage snapshot-sources, because pin-discovery builds exactly that stage, so the candidates it reports are the ones the image installs. The apt-base install list keeps plain package names: `tool_03_dockerfile_installs_every_apt_pin` matches whole words, so a `qemu-user/<suite>` spelling would break it.
- **qemu-system-arm moves too:** D-31's scope names it; qemu-system-arm, qemu-system-common and qemu-system-data come from the same `qemu` source and must share one version; one QEMU release for user mode now and system mode later (Phase 5 emulator replay, R6) keeps one set of CPU-model semantics and one licence notice.
- **Pinned set:** priority 990 for exactly `qemu-user qemu-system-arm qemu-system-common qemu-system-data` (the qemu-source packages the current image has installed, per the dpkg capture in tool-outputs.toml), priority -1 for every other backports package. A backports dependency outside the set therefore fails the build loudly instead of entering silently.
- **Proof before publish:** a minimal probe in the container workflow's image-a job (a 10-line Thumb guest, `container/smoke/qemu-mprofile.S`, exit code 42 through raw `svc`), not the 03-01 self-test: testbed pulls only the digest under `## Current image`, so the full self-test cannot see a branch-built image. The probe tests exactly the D-31 cause (startup abort) and gates the publish. Measured at planning time on this host (QEMU 8.2.2, GCC 13.2.1): `arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -nostdlib -static` of that guest runs under `qemu-arm -cpu cortex-m4 -R 0x10000000` and exits 0 for `movs r0, #0` and 42 for `movs r0, #42` (the exit code propagates; entry 0x8001).
- **Version rule:** accept the pin-discovery candidate when qemu-user and qemu-system-arm show the same version, it contains `~bpo12`, and its upstream major is at least 8 (the planning context's floor; the fix is absent from 7.2). An upstream 8.2.x is D-31 as written. Any other accepted version (for example 9.x or 10.x, because backports tracks the next stable) is recorded as a deviation from D-31's "8.2.x, as measured on the host" with the `qemu-mprofile` result as its in-image evidence; plan 03-10 puts it in the PR body and in the merge checkpoint text, so the founder sees it before the costly merge and can refuse. The informational `qemu-backports` notice lists every qemu-user `~bpo12` version the snapshot archive has seen and when, so the founder can tell whether an 8.2.x exists at another timestamp.
- **Fixtures:** taken from round trip 1's `tool-outputs` notices. Round trip 1 already builds the final image definition (the `[apt]` table and the tool rows are not build arguments; `mt toolchain build-args` renders only `[image]`, `[llvm]`, `[rust]` and `[source.*]` values), so its captures are real outputs of the image round trip 2 builds. Round trip 2 confirms they are equal.

## CI round trip (protocol of plans 02-17..02-22 and 03-01; stated here in full)

1. Commit. Push only when `git rev-parse --abbrev-ref HEAD` prints `claude/gsd-discuss-phase-1-mzdw5v`, and only with `git push -u origin claude/gsd-discuss-phase-1-mzdw5v`. Never force, never push main, never rebase, never open a PR in this plan, never create or push another branch. On a network failure retry the same push up to 4 times, waiting 2 s, 4 s, 8 s and 16 s; then stop and report.
2. `SHA=$(git rev-parse HEAD)`; list its runs with `gh api "repos/sat-wik/migrationtool/actions/runs?head_sha=${SHA}&per_page=50" --jq '.workflow_runs[] | [.id, .path, .status, .conclusion] | @tsv'`.
3. Poll every 60 s (one Bash call is limited to 10 minutes) until the awaited runs are `completed`. A run still going 15 minutes after its `timeout-minutes` (image-a and image-b: 120) is stuck: stop and report.
4. Jobs: `gh api repos/sat-wik/migrationtool/actions/runs/<run_id>/jobs --jq '.jobs[] | [.id, .name, .conclusion] | @tsv'`; per-step conclusions with `--jq '.jobs[] | .name as $j | .steps[] | [$j, .name, .conclusion] | @tsv'`.
5. Annotations: `gh api --paginate repos/sat-wik/migrationtool/check-runs/<job_id>/annotations --jq '.[] | "== " + .title + "\n" + .message'`. Join the parts of one title with a newline, in order. A missing title means the step must be split or did not run, never that it passed.
6. Evidence comes only from `gh api repos/sat-wik/migrationtool/actions/...` and check-run annotations; log and artifact hosts are blocked and there is no local Docker. Any `gh api` failure: stop and report, asking the founder to paste the job conclusions and annotation text. A missing run, a skipped job or an unreadable result is never green and does not count as a round trip.
