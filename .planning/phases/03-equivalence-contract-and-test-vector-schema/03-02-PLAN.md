## Claude's discretion settled here (record each in the SUMMARY)

- Policy TOML shape (research Q7, plus D-29):
  - top level: `schema_version = 1`, `contract_version = "0.1.0"`, `module = "<manifest target id>"`, table `[ub]`;
  - `[ub] default_action = "return_error" | "panic" | "preserve"`;
  - `[ub.default_change]`: `module` (the "where", equal to the file's module), `reason`, `approver`, `date`;
  - `[[ub.error_code]]`: `function` (C identifier), `value` (a decimal integer or a C identifier naming a constant); the declared code that return_error returns (D-17). Defined and syntax-checked now; the committed policies leave it empty and Phase 4's UB decisions log fills it. Name this in the SUMMARY as an assumption for the founder.
  - `[[ub.override]]`: `function`, `kind`, `location`, `action`, `reason`, `approver`, `date`. `kind` and `location` are free non-empty text now; Phase 4 constrains them. Site identity is exact equality of the three strings.
- `contract_version` must be `MAJOR.MINOR.PATCH` (digits) and not greater than `CONTRACT_VERSION`.
- `module` must match `^[a-z0-9][a-z0-9_-]*$`; `Policy::load(path)` also requires it to equal the file stem.
- Dates: `YYYY-MM-DD` with a real calendar day (Gregorian leap years), checked without a clock and without a date crate.
- lib_state value shapes (D-06), fixed here once and implemented by mt-vectors in plan 03-03:
  - integer, enum, bool or char of at most 32 bits: `{"type": "<C type>", "value": <JSON integer>}`; 64-bit: `"value": "<decimal string>"`;
  - `float`/`double`: `{"type": .., "bits": "<IEEE bit pattern, lowercase hex>"}`;
  - array of a 1-byte element type: `{"type": .., "hex": "<lowercase hex>"}`; other arrays: `{"type": .., "items": [..]}`;
  - struct: `{"type": "struct X", "fields": {"<member>": <value>, ..}}`; a union records every member decoded from the same bytes;
  - pointer: `{"type": "T *", "pointer": null}`, `{"type": .., "pointer": {"buffer": "<region>", "offset": <n>}}` with region `in`, `out`, a declared state or local name, `heap`, or `global:<object>:<symbol>`, or `{"type": .., "pointer": {"symbol": "<function>"}}`;
  - a field marked unobserved: `{"type": .., "unobserved": "<reason>"}`; unobserved fields are not compared and are counted in the provenance;
  - reserved top-level names: `globals` (writable globals whose bytes differ from the image's initial bytes, keyed `<object path>:<symbol>`), `ret` (a struct returned by value, the full value of a return wider than 32 bits, or a returned pointer classified like any pointer), `heap` (objects in the driver's `_sbrk` arena reachable from recorded pointers through typed edges, keyed by decimal offset, each decoded with its pointee type; a `char` pointee is recorded as the NUL-terminated bytes in hex; a walk cap of 4096 objects, beyond which the remaining pointers are unobserved with a reason) and `in` (the input buffer's bytes after the call, only for an input the adapter declares mutable).
- Outcome classes written in `stderr` as `outcome=<class>` followed by fixed detail words: `ok`, `fault`, `abort`, `timeout`, `setup_failed` (from plan 03-01's `OUTCOME_CLASSES`); `executor_error` is never a vector. `has_ub` labels from plan 03-01: `crash:SIGSEGV`, `crash:SIGBUS`, `crash:SIGILL`, `crash:SIGFPE`, `crash:SIGABRT`, `oob-write:guard-slack`, `timeout`. A timeout vector has `rc = -9`. A setup_failed vector carries no label and is compared.
- The contract states the user-mode distinction instead of editing `container/pins.toml`: unmodified firmware images cannot run in qemu-arm user mode; the reference driver is a hosted-style static ELF reusing the same object code.
- Contract changes later in this phase: a plan that needs a contract change bumps the patch version, adds a changelog line and moves `CONTRACT_VERSION` and the 16 policies together; the doc test keeps them equal.
