## Decisions this plan implements (03-CONTEXT.md, LOCKED)

- D-06 (reversibility: costly, decided): lib_state field by field, C type and exact value, pointers as `{buffer, offset}` into a named buffer, never raw addresses.
- D-09: state structs recorded with every field their header defines, laid out as the compiled C for ILP32 (from DWARF); a field may be marked unobserved only with a recorded reason, and the contract counts such marks.
- D-10: every writable global found automatically and snapshotted (plan 03-04), now typed.
- D-11: roles in the manifest, driver generated.
- D-29: layout from the pinned GCC's DWARF read by `llvm-dwarfdump` through the runner (GCC's 1-byte enums differ from clang's); ELF symbols with the locked `object` crate; no new crates.

## Claude's discretion settled here (record each in the SUMMARY)

- Manifest additions (additive, no schema bump):
  - `Role::State`: a pointer parameter to a struct or union; `name` required (C identifier, not reserved); the pointee type is the parameter text with one top-level `*` and any `const` removed, and it must match `^(struct |union |enum )?[A-Za-z_][A-Za-z0-9_]*$` before it is written into the driver or the probe (otherwise the entry is not expressible; plan 03-07 generalizes this into the closed type grammar).
  - `[[target.X.entry.unobserved]]` with `field` (`<state name>(.<member>|[<index>])+`, C identifiers and decimal indices only) and `reason` (non-empty); `UnobservedMark` and `Entry.unobserved` (`skip_serializing_if = "Vec::is_empty"`).
- Initial roles, each with a comment naming D-09 and D-11:
  - microcoap `coap_parse (coap_packet_t *, const uint8_t *, size_t)`: state `pkt`, in_buf, in_len.
  - nimble `ble_uuid_init_from_buf (ble_uuid_any_t *, const void *, size_t)`: state `uuid`, in_buf, in_len.
  - tinycbor `cbor_parser_init (const uint8_t *, size_t, uint32_t, CborParser *, CborValue *)`: in_buf, in_len, scalar `flags` with `default = 0` (sweep left empty unless the executor finds a documented validation flag that changes behavior; record the choice), state `parser`, state `it`.
- Probe: `render_probe(include_lines, &[(name, type_text)])` gives the include lines then, for each state, `<type> mt_probe_<name> __attribute__((used));`; `probe_flags` equals the driver's flags (plan 03-04's `driver_flags` plus the baseline), plus `-g -gdwarf-5 -O0 -c`; the scratch object and the dump live under the entry's build directory; the dump goes through the runner with the default 16 MiB cap, and a truncated or incomplete dump is an error.
- Parser: `parse_dwarfdump(text) -> Result<LayoutModel, LayoutError>` reads DIE header lines (`0x<offset>: <indent>DW_TAG_*`) and attribute lines (`DW_AT_*` followed by a tab and a parenthesized value, with type references as `(0x<offset> "<name>")`), building a DIE tree by indentation; it handles `DW_TAG_base_type` (`DW_AT_encoding`, `DW_AT_byte_size`), `DW_TAG_enumeration_type` (size; underlying type when given), `DW_TAG_structure_type`, `DW_TAG_union_type` and their `DW_TAG_member` (`DW_AT_data_member_location`, `DW_AT_bit_size`, `DW_AT_data_bit_offset`), `DW_TAG_array_type` with `DW_TAG_subrange_type` (`DW_AT_upper_bound` or `DW_AT_count`), `DW_TAG_typedef`, `DW_TAG_const_type`, `DW_TAG_volatile_type`, `DW_TAG_pointer_type`, `DW_TAG_subroutine_type`, `DW_TAG_variable`; any other tag reached through a recorded type is `LayoutError::Unsupported` naming it (fail closed). Anonymous members are named `_anon<offset>`.
- Decoder: `decode_value(model, type, bytes, &Regions) -> StateValue` per the contract's shapes: integers by encoding and size (signed values sign-extended; 64-bit as decimal strings), enums as integers of their size, bool and char as integers, float and double as bit patterns, arrays of a 1-byte element as hex, other arrays as items, structs as fields in declaration order (a BTreeMap by name in JSON), unions with every member, bitfields extracted little-endian from `DW_AT_data_bit_offset` and `DW_AT_bit_size` and sign-extended when their base type is signed.
- Pointer classification `classify_pointer(value, &Regions)`: 0 is null; inside a named region `[base, base + len]` (one past the end included) gives `{buffer, offset}`; an address equal to a function symbol of the linked driver with the Thumb bit cleared gives `{symbol}`; anything else is unobserved with the reason `pointer outside known regions`. Regions: `in`, `out`, each state by name, `heap` (the `_sbrk` arena), each dumped global as `global:<object>:<symbol>`. The region bases are the template's fixed constants and the linked ELF's symbol addresses, so classification is reproducible.
- Globals typing at build time: for each writable global of the pair, the canonical compile command whose output is its object is re-run with its own arguments, `-o` pointed at a scratch object under the build directory, any `-O*` replaced by `-O0`, plus `-g -gdwarf-5` (DWARF types do not depend on the optimisation level); the variable's DIE is joined by name (a function-local static `name.N` joins the `DW_TAG_variable` named `name` inside a subprogram only when exactly one matches); types go into build.json; a global that cannot be typed is recorded as untyped there, and plan 03-04's fail-closed rule applies if it changes.
- Layout notice: `mt vectors layouts --work-dir <DIR>` prints, for every built entry and state, `<target>/<config>/<entry> <state> <type> size=<n> <member>@<offset>:<size>[:<bit offset>:<bit size>] ...` in a fixed order, from build.json.
