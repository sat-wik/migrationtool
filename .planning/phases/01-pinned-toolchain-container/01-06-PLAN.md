## CI round trip (used by Task 3 here and by plans 01-07 and 01-08)

1. Commit. Read `ci_push_mode` from 01-02-SUMMARY.md. `executor-pushes`: run `git push origin HEAD` (current phase branch only, never force, never main). `founder-pushes`: return a checkpoint:human-action asking the founder to push the branch at the printed commit, then continue.
2. Capture the commit: `SHA=$(git rev-parse HEAD)`. Find runs: `gh api "repos/sat-wik/migrationtool/actions/runs?head_sha=${SHA}&per_page=50" --jq '.workflow_runs[] | [.id, .path, .status, .conclusion] | @tsv'`.
3. Poll every 60 s (background loop or repeated calls; a single Bash call is limited to 10 minutes) until each expected run has status `completed`. A run still queued or in progress after its workflow's `timeout-minutes` plus 15 minutes is stuck: stop with a checkpoint:human-action.
4. Job results: `gh api repos/sat-wik/migrationtool/actions/runs/<run_id>/jobs --jq '.jobs[] | [.id, .name, .conclusion] | @tsv'`.
5. Data and failure tails: `gh api repos/sat-wik/migrationtool/check-runs/<job_id>/annotations --jq '.[] | "== " + .title + "\n" + .message'`. Workflows in this phase publish discovery output, manifests, captured tool outputs, failure tails and the image digest as annotations because the Actions log and artifact hosts are not reachable from cloud sessions.
6. If a `gh api` call fails (HTTP 403, 5xx or a proxy error), stop with a checkpoint:human-action asking the founder to paste the job conclusions and annotation text from the run page. A missing run, a skipped job or an unreadable result is never treated as green.
