## CI round trip (same protocol as plan 01-06)

1. Commit. Read `ci_push_mode` from 01-02-SUMMARY.md. `executor-pushes`: `git push origin HEAD` (current phase branch only, never force, never main). `founder-pushes`: return a checkpoint:human-action asking the founder to push the branch at the printed commit.
2. `SHA=$(git rev-parse HEAD)`; list runs with `gh api "repos/sat-wik/migrationtool/actions/runs?head_sha=${SHA}&per_page=50" --jq '.workflow_runs[] | [.id, .path, .status, .conclusion] | @tsv'`.
3. Poll every 60 s until each expected run is `completed`; a run still going after its timeout-minutes plus 15 minutes is stuck: checkpoint:human-action.
4. Jobs: `gh api repos/sat-wik/migrationtool/actions/runs/<run_id>/jobs --jq '.jobs[] | [.id, .name, .conclusion] | @tsv'`.
5. Annotations: `gh api repos/sat-wik/migrationtool/check-runs/<job_id>/annotations --jq '.[] | "== " + .title + "\n" + .message'` (log and artifact hosts are unreachable from cloud sessions, so workflows publish tables, manifests, captures and failure tails as annotations).
6. Any `gh api` failure: checkpoint:human-action asking the founder to paste job conclusions and annotation text. A missing run, a skipped job or an unreadable result is never green.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet downloads -> image build | rustup-init, channel manifests, crates, Arm tarball, git sources fetched during the build |
| image -> host runner | the check and smoke steps run tool binaries from the image with repository files mounted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-22 | Tampering | Dockerfile downloads | high | mitigate | `sha256sum -c` against pins for rustup-init, both channel manifests, both .crate files and the Arm tarball; `rev-parse HEAD` checks for KLEE and klee-uclibc; cargo `--locked`; lint tests enforce all three patterns |
| T-01-23 | Tampering | c2rust exporter fetching tinycbor during the build | medium | mitigate | the tinycbor commit is pinned inside c2rust 0.22.1 (crate sha256-verified) and the build asserts the exporter's CMakeLists carries the pinned TINYCBOR_COMMIT |
| T-01-24 | Elevation of privilege | check and smoke containers | medium | mitigate | `docker run --rm --network none --user 65534:65534` with read-only mounts for mt, pins and the repository; only /out and /tmp writable |
| T-01-25 | Information disclosure | build logs and annotations | low | accept | annotations carry tool versions, manifests and build tails only; no secrets exist in these jobs (permissions contents: read, no registry login in this plan) |
| T-01-SC | Tampering | cargo installs in the image (c2rust, cargo-mutants) | high | mitigate | c2rust installed only with `c2rust_legitimacy: approved` (precondition, plan 01-02); exact versions, crate sha256 verified before `cargo install --locked` |
