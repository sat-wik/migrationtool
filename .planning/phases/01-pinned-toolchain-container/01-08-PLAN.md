  <action>
In `.github/workflows/container.yml`: give `image-a` (only) job-level `permissions: contents: read, packages: write`. After its check, off-pin, manifest and smoke steps have passed, and only when the event is not pull_request: log in to ghcr.io with docker/login-action (SHA-pinned; username `${{ github.actor }}`, password `${{ secrets.GITHUB_TOKEN }}`), tag the loaded image `ghcr.io/sat-wik/migrationtool-toolchain:sha-${{ github.sha }}` (lowercase repository path), `docker push` it, read the pushed digest from `docker inspect --format '{{index .RepoDigests 0}}'`, expose it as a job output and publish notice `image-digest`. The pushed image is the exact image that passed the checks; never rebuild for publishing. In `compare`, after manifest-diff succeeds and when a digest was pushed, publish notice `verified-image` with `ghcr.io/sat-wik/migrationtool-toolchain@sha256:<digest>` and the manifest sha256. No other job gets `packages: write`; no personal access token is used.

Write `container/README.md` (Docker only per D-05; linux/amd64 only per D-22): what the image contains (each tool with its pin source in container/pins.toml; LLVM 16 is provisional per PROJECT D-15 until the Phase 6 R1 verdict; Hayroll and Kani not installed with the reasons from pins, D-10); the reproducibility guarantee stated as manifest-identical builds (D-06: two builds from the same inputs produce byte-identical tool-version manifests; binary-level identity of installed tools is not claimed); how to pull and run on Apple Silicon (`docker pull --platform linux/amd64 ghcr.io/sat-wik/migrationtool-toolchain@sha256:<digest>`, emulation is slow, `docker login ghcr.io` if the package is private, how to obtain a static `mt` — download the `mt` artifact of the verified run or build it inside the image with `cargo build --release --locked -p mt-cli --target x86_64-unknown-linux-musl` — and run `mt toolchain check --pins /opt/mt/pins.toml` with mt and pins mounted read-only); the slow local build fallback (render args with `mt toolchain build-args --pins container/pins.toml`, pass each line as `--build-arg`, `docker buildx build --platform linux/amd64 --target final container/`); pin bumps (D-20: hand-edited PR to container/pins.toml, recompute checksums with `mt toolchain hash <url>`, the pin-discovery workflow prints apt candidates and the Arm checksum, the container workflow rebuilds twice and diffs manifests; no Renovate or Dependabot; D-21: changing [llvm].major or [rust.bitcode].version needs a new PROJECT.md decision line with matching `llvm=` and `bitcode-rustc=` tokens or cargo test fails); notices: tools under GPL licences (Bear, QEMU, the Arm GNU toolchain) and the other tools run only as subprocesses inside the container and are never linked into mt — take each licence name from the project's own copyright or LICENSE file inside the image or upstream, not from memory; a "Current image" section filled in Task 2.

Add `tool_03_container_readme_states_manifest_identical_and_makes_no_certification_claim` to container_static.rs: the README contains "manifest-identical" and "provisional", and, compared case-insensitively, contains none of the words reserved by PROJECT D-13 nor the phrase "bit-for-bit reproducible" (keep the forbidden word list inside the test only).
